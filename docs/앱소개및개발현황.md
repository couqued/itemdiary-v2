# 아이템 다이어리 — 앱 소개 및 개발 현황

## 앱 개요

**아이템 다이어리**는 구매한 물건이나 구매 예정 아이템을 기록하고 관리하는 개인 소비 기록 앱입니다.

- **패키지명**: com.openended.keep_product
- **플랫폼**: Android (Google Play 배포 중) / iOS (추후 배포 예정)
- **프레임워크**: React Native
- **백엔드**: Supabase (PostgreSQL + Auth + Storage)
- **외부 API**: 네이버 검색 API (쇼핑/도서)

## 기능 상세

### 인증
- 이메일/비밀번호 회원가입 (이메일 인증)
- 로그인 / 로그아웃
- **비밀번호 찾기** — 이메일로 재설정 링크 발송, 딥링크(itemdiary://reset-password)로 앱 복귀 후 재설정
- 회원 탈퇴 — 비밀번호 재확인 → 아이템 데이터 삭제 → 계정 삭제(RPC) → 로그아웃

**비밀번호 찾기 동작 흐름**:
```
로그인 화면 → "비밀번호를 잊으셨나요?" 탭
→ ForgotPasswordScreen (이메일 입력 → 재설정 링크 발송)
→ 이메일의 링크 클릭
→ 앱 딥링크로 복귀 (itemdiary://reset-password#access_token=...&type=recovery)
→ ResetPasswordScreen (새 비밀번호 입력)
→ 변경 완료 → 자동 로그아웃 → 새 비밀번호로 로그인
```

### 홈 탭 (아이템 목록)

**아이템 / 찜 탭 분리**
- 구매 완료된 아이템과 찜(위시리스트) 목록을 탭으로 분리

**목록 표시**
- 그리드(2열) / 리스트 전환 (설정 AsyncStorage에 저장)
- 무한 스크롤 (페이지네이션)
- 당겨서 새로고침

**검색**
- 아이템 이름 실시간 검색 (debounce 300ms)

**필터 / 정렬**
- 카테고리 칩으로 필터링
- 정렬: 최신순 / 구입날짜순 / 가격순 / 이름순

**아이템 등록 (Speed Dial FAB)**
- FAB 버튼 → 직접 등록 / 바코드 스캔 선택

### 아이템 등록/수정 (ItemFormScreen)

**입력 항목**
- 사진 (갤러리에서 선택 → Supabase Storage 업로드)
- 이름 (필수, 최대 20자)
- 구입날짜 / 등록날짜 (오늘/어제 퀵버튼 제공)
- 가격 (숫자 자동 포맷팅)
- 구입처 (쿠팡, 무신사 등, 최대 30자)
- [선택] 카테고리 칩 선택
- [선택] 링크 (상품 URL)
- [선택] 메모 (최대 200자)
- 아이템 / 찜 구분

**바코드 자동 입력**
- 바코드 스캔 → 네이버 API 조회 → 이름, 가격, 이미지, 구입처, 카테고리 자동 입력

### 바코드 스캔 (BarcodeScanScreen)

- react-native-vision-camera로 실시간 카메라 스캔
- 지원 바코드: EAN-13, EAN-8, UPC-A, UPC-E, Code-128, QR
- ISBN(978/979) 감지 시 도서 API로 자동 전환
- 네이버 쇼핑/도서 API 연동 → 상품 정보 자동 파싱
- 네이버 카테고리 → 앱 카테고리 자동 매핑
- 인식 성공 시 초록색 테두리 피드백

**카테고리 자동 매핑 기준**
| 네이버 대분류 | 앱 카테고리 |
|---|---|
| 의류/패션의류 | 의류 |
| 디지털/가전 (PC, 모바일, 음향, 카메라) | 전자기기 |
| 디지털/가전 (기타) | 가전 |
| 가구/인테리어 | 가구 |
| 패션잡화 → 신발 | 신발 |
| 패션잡화 → 가방 | 가방 |
| 식품 | 식품 |
| 도서 | 도서 |
| 화장품/미용 | 뷰티 |
| 생활/건강 | 생활용품 |

## Supabase 사용 현황

### Auth
| 기능 | API |
|---|---|
| 회원가입 | `supabase.auth.signUp()` |
| 로그인 | `supabase.auth.signInWithPassword()` |
| 로그아웃 | `supabase.auth.signOut()` |
| 세션 조회 | `supabase.auth.getSession()` |
| 사용자 조회 | `supabase.auth.getUser()` |
| 상태 구독 | `supabase.auth.onAuthStateChange()` |
| 비밀번호 재설정 이메일 | `supabase.auth.resetPasswordForEmail()` |

| 세션 복원 (딥링크) | `supabase.auth.setSession()` |
| 계정 삭제 | `supabase.rpc('delete_user')` |

### Database — items 테이블 스키마
```sql
CREATE TABLE items (
  seq        BIGSERIAL PRIMARY KEY,
  user_id    TEXT NOT NULL,
  name       TEXT,
  price      INTEGER,
  item_date  DATE,
  memo       TEXT,
  link       TEXT,
  image_url  TEXT,
  store_name TEXT,
  category_id INTEGER REFERENCES categories(id),
  is_favorite BOOLEAN DEFAULT false,
  is_wishlist BOOLEAN DEFAULT false,
  updated_at  TIMESTAMPTZ DEFAULT NOW(),
  created_at  TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_items_is_wishlist ON items(is_wishlist);
```

**DB 필드명 매핑** (2026-04-04 마이그레이션 시 변경):

| SEQ | seq |
| USER_ID | user_id |
| TITLE | name |
| DATE | item_date |
| PRICE | price |
| LINK | link |
| MEMO | memo |
| IMAGE_FILE_PATH | image_url |

### Database — Supabase Functions (RPC)
```sql
-- 회원 탈퇴 시 Auth 계정 삭제
CREATE OR REPLACE FUNCTION delete_user()
RETURNS void LANGUAGE plpgsql SECURITY DEFINER AS $$
BEGIN
  DELETE FROM auth.users WHERE id = auth.uid();
END;
$$;
```

### RLS 정책
```sql
-- items: 본인 데이터만 접근
CREATE POLICY "본인 데이터만 접근"
  ON items FOR ALL
  USING (user_id = (SELECT email FROM auth.users WHERE id = auth.uid()));

-- categories: 로그인한 사용자 누구나 읽기 가능
CREATE POLICY "categories_read_all"
  ON categories FOR SELECT TO authenticated USING (true);
```

## Supabase 무료 티어 한도

| 기능 | 무료 한도 | 비고 |
|---|---|---|
| Auth MAU | 50,000명 | 개인 앱 초기에는 사실상 무제한 |
| Database | 500MB | 이미지는 Storage에 저장 → DB는 여유로움 |
| Storage | 1GB | 이미지 1장 200~500KB → 약 2,000~5,000장 |
| Edge Functions | 월 500,000건 | CPU 시간 50ms/건 (네트워크 I/O 미포함) |
| Bandwidth | 월 5GB | 이미지 로딩이 주 사용처 |
| 프로젝트 | 활성 2개 | 7일간 API 호출 없으면 자동 일시정지 |

**유료 전환 기준** (Pro 플랜 $25/월):
- Storage 1GB 초과 시 (개별 업그레이드 불가 — 플랜 전체 업그레이드 필요)
- MAU 50,000명 초과 시
- Edge Function 500K 초과 시

**결론**: 사용자 수천명 수준까지 무료 운영 가능. Storage가 가장 먼저 한도 도달 가능성 있음.
